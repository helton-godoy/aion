## 2025-02-27 - [Optimize File Operations in SafetyProtocol]
**Learning:** When performing parallel file I/O over arrays of paths, checking `fs.pathExists` before execution generates a race condition and adds unnecessary latency compared to capturing an `ENOENT` error. Additionally, concurrent reads using unbounded `Promise.all` can trigger `EMFILE` limits and mess with object key order if keys are assigned inside the async block.
**Action:** Used chunked `Promise.all` (chunk size 20) with pure `try/catch` catching `ENOENT`. Then collected the chunked results and populated the `state.files` mapping synchronously to ensure deterministic key insertion order. Used this approach to replace `pathExists` blocks in `captureCurrentState` and `loadCommitTracker` reducing latency and improving data consistency.
