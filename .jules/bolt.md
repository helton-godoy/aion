## 2024-05-12 - Sequential vs Chunked Parallel I/O in Rollback States
**Learning:** In AION's `SafetyProtocol`, the `captureCurrentState` function previously read each file sequentially using a `for...of` loop with redundant `pathExists` checks. When scaling up to large commits with many files, this created a significant bottleneck and increased the risk of TOCTOU (Time of Check, Time of Use) race conditions. Converting this entirely to unbounded `Promise.all` runs the risk of EMFILE errors.
**Action:** Always process large sets of file operations using chunked `Promise.all` batches (e.g., chunks of 20) combined with native `ENOENT` try/catch handling instead of `pathExists`. Ensure the chunk results are synchronized back into state objects sequentially to preserve deterministic key ordering required for hash consistency.
