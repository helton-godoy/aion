## 2024-05-18 - fs-extra Native Rejections Performance Optimization
**Learning:** Utilizing optimized `fs-extra` and Node.js native errors (e.g. `ENOENT`) via `try/catch` is significantly more performant than performing sequential `fs.pathExists` checks prior to disk reads or file deletion operations. Eliminating unnecessary system calls inside loop iterations decreases application latency when conducting repetitive I/O, especially inside concurrent `Promise.all` operations which also avoids race conditions.
**Action:** When working on heavily relied on file reading operations, omit redundant conditional existence checks (`pathExists`) when reading, and handle `ENOENT` codes explicitly to gracefully proceed. Additionally, leverage `Promise.all` over object iteration for concurrent asynchronous resolutions when multiple independent `fs` operations (like `fs.readFile` and `fs.stat`) on the same path are invoked. Use chunking or loop-based synchronous assignments only for insertion order guarantees when writing dictionary-like states.
