## 2024-07-08 - [Optimize state capture I/O]
**Learning:** In AION's `SafetyProtocol.captureCurrentState`, capturing state for large batches of files sequentially (`await fs.pathExists` then `await fs.readFile` & `fs.stat`) caused significant I/O overhead. Optimizing with chunked `Promise.all` (max 20) and removing redundant `pathExists` checks (handling `ENOENT` natively) massively reduced capture latency. However, it's crucial to collect the promise results synchronously *after* resolution to preserve deterministic key insertion order in the `state.files` object for consistent change tracking hashing.
**Action:** Always prefer chunked `Promise.all` for batch file processing to optimize disk I/O while preventing EMFILE exhaustion. Avoid double I/O checks like `pathExists` prior to reading; use `try/catch` with `ENOENT`. Preserve deterministic object structures if serialization/hashing is downstream by syncing promises into an array before object assignment.
