## 2024-05-14 - [I/O Optimization] fs.pathExists vs Direct ENOENT Handling & Concurrent Promises
**Learning:** Checking `fs.pathExists` before invoking `fs.readFile` or `fs.stat` adds unnecessary redundant file system calls and is a known Node.js anti-pattern for performance optimization. Relying natively on the `ENOENT` error natively thrown by `fs` operations during I/O effectively removes 1 unnecessary disk hit per file operation. Also, executing independent I/O checks like `fs.readFile` and `fs.stat` inside a chunked `Promise.all` array ensures scalable parallel disk I/O optimization while preventing `EMFILE` memory exhaustion bottlenecks when capturing large file state changes.
**Action:** Default to attempting file system actions (`fs.readFile`, `fs.stat`, `fs.readJSON`) directly using `try/catch` blocks matching `error.code === 'ENOENT'` instead of executing preliminary `fs.pathExists` boolean verifications. Batch bulk file array manipulations using chunked `Promise.all` loops instead of sequential iteration.
