## 2024-04-01 - [Avoid Redundant fs.pathExists Before Read/Stat]
**Learning:** Checking file existence with `fs.pathExists` before performing an action like `fs.readFile` or `fs.stat` is an antipattern that causes unnecessary I/O overhead. By executing an operation immediately and catching `ENOENT` (Error NO ENTry), you save an entire system call, effectively halving the disk I/O cost. In heavily hit paths such as loading context or rollback states in AION, this micro-optimization scales up.
**Action:** When implementing or refactoring Node.js file system logic, use `try/catch` around `fs.readFile` or `fs.stat` and handle `error.code === 'ENOENT'` instead of performing proactive check logic (`fs.pathExists()`). Also ensure to test these cases with `fs.readFile.mockRejectedValue(Object.assign(new Error('ENOENT'), { code: 'ENOENT' }))`.
