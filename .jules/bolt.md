## 2024-03-24 - Optimize I/O concurrency in rollback state capture
**Learning:** During micro-commits and rollback point generation, `RollbackManager.captureCurrentState` repeatedly executed sequential `fs.pathExists`, `fs.readFile`, and `fs.stat` for each file change. While modifications (writes/rollbacks) must remain strictly sequential to avoid race conditions, read operations for capturing state are independent. A chunked concurrency approach (e.g., chunks of 20 using `Promise.all`) prevents EMFILE limits while drastically speeding up the capture process compared to a pure `for...of` loop.
**Action:** When working on file state snapshotting or read-only validation loops across multiple files, identify if operations can safely occur out-of-order. If so, replace sequential `for...of` loops with a chunked `Promise.all` logic, retaining deterministic key ordering if needed by collecting promises into an array first.
