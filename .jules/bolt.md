## 2023-11-09 - [Optimizing Disk I/O by avoiding double access checks and implementing parallel chunked reads]
**Learning:** Found a core pattern where files were being checked for existence (`fs.pathExists`) sequentially, immediately followed by `fs.readFile` and `fs.stat`. This represents a double I/O tax in `SafetyProtocol` and `RollbackManager`.
**Action:** When performing file operations, do not use `fs.pathExists` prior to reading. Rely natively on `try...catch` dealing with `ENOENT` natively. For batch file reads and states, always process the list in `chunked` `Promise.all` batches (to avoid EMFILE) and then push into the synchronous object/dictionary sequentially to maintain deterministic iteration insertion order. Mocking these tests required specifically simulating `fs.readJSON` or `fs.readFile` throwing `Object.assign(new Error('ENOENT'), { code: 'ENOENT' })` in Jest.
