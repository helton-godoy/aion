## 2025-06-02 - Avoiding Double I/O with fs.pathExists
**Learning:** Using `fs.pathExists` before `fs.readFile` or `fs.stat` causes double I/O and degrades performance significantly, especially when processing many files during state capture operations (like in `SafetyProtocol.captureCurrentState`). Catching native `ENOENT` errors natively from `Promise.all([fs.readFile(), fs.stat()])` is substantially faster. Also, using unbounded concurrency mapping array of files to Promises can cause `EMFILE` errors.
**Action:** When reading files, skip `fs.pathExists`. Instead, use `try/catch` or `.catch()` handling `ENOENT`. When dealing with multiple files concurrently, use chunked `Promise.all` (e.g., chunks of 20) and collect results to populate state synchronously for deterministic key ordering.
