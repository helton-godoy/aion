## 2024-11-20 - [Node.js I/O Optimization Pattern in AION]
**Learning:** We identified a widespread, architecture-level anti-pattern in the AION codebase concerning I/O operations (particularly in `SafetyProtocol` and `MemoryManager`). The application heavily relied on `fs.pathExists()` checks immediately preceding `fs.readFile()` or `fs.readJSON()` operations. This double I/O drastically impacts performance in high-frequency safety checks or state reads, while also introducing subtle Time-Of-Check to Time-Of-Use (TOCTOU) race condition vulnerabilities.
**Action:** When optimizing disk I/O in Node.js, structurally prefer the `try/catch` approach natively handling `ENOENT` over explicitly verifying file presence first. Furthermore, in state captures where both file contents and file stats are required (`readFile` and `stat`), always bundle them with `Promise.all` to allow concurrent file system execution.
