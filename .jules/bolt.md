## 2023-10-24 - fs-extra I/O Performance Optimization
**Learning:** Checking \`fs.pathExists\` before performing an I/O operation like \`fs.readJSON\` or \`fs.readFile\` creates redundant I/O overhead. Additionally, when processing arrays of file operations, doing them sequentially is suboptimal.
**Action:** Instead of \`fs.pathExists\`, rely on native Node.js \`try/catch\` blocks handling \`ENOENT\` errors directly on the primary operation (e.g., \`readJSON\`, \`readFile\`). Use \`Promise.all\` with chunking for large arrays to execute concurrent, optimized disk reads while keeping memory usage stable, and remember to structure Jest mocks appropriately using \`mockRejectedValue(Object.assign(new Error('ENOENT'), { code: 'ENOENT' }))\` when writing tests for these optimized code paths.
